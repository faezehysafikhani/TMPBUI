# پلن تست — برنچ `feature/missing-capabilities`

این پلن هر چیزی را که در این برنچ (Core و UI) اضافه یا عوض شده پوشش می‌دهد، به‌علاوهٔ قابلیت‌های قبلی که
ممکن است از این تغییرات اثر گرفته باشند (رگرسیون). هر ردیف یک شناسه دارد تا نتیجه را بشود کنارش ثبت کرد:
✅ درست، ❌ خطا (با توضیح و اسکرین‌شات)، ⏭ اجرا نشد (با دلیل).

**اولویت‌ها:** P1 = پیش از انتشار حتماً، P2 = مهم، P3 = در صورت وقت.

---

## ۰. آماده‌سازی محیط

| شناسه | کار | نتیجهٔ مورد انتظار |
|---|---|---|
| ENV-01 | از یک **کپی دیتابیس production** روی محیط تست استفاده کنید (با `tools/restore.ps1 -Database TMPB_Test -SkipFiles` یا backup معمول) | دیتابیس بالا می‌آید |
| ENV-02 | اگر دیتابیس با اسکریپت مدیریت می‌شود: `db/check-upgrades.sql` را اجرا کنید و مراحل جاافتاده را به ترتیب بزنید (تا `upgrade-21-workflow.sql`) | خروجی: «all 21 steps applied» |
| ENV-03 | API (TMPB-API) و UI را از همین برنچ build و نصب کنید. UI: `npm ci && npm run build`، سپس محتوای `dist` روی IIS | هر دو بالا می‌آیند؛ `/health` پاسخ `ok` |
| ENV-04 | تنظیمات: `Identity:AdminPassword`، `DataProtection:KeysPath`، `FileStorage:RootPath`، `Cors:AllowedOrigins` و `.env` UI | ورود با admin ممکن است |
| ENV-05 | سه کاربر تست بسازید: **مدیر سیستم**، **مدیر واحد** (مدیر مستقیم کاربر بعدی در چارت)، **کارشناس عادی** (بدون دسترسی‌های مدیریتی) | — |
| ENV-06 | DevTools مرورگر را باز نگه دارید (Console و Network) | در طول تست: هیچ خطای قرمز Console، هیچ پاسخ 5xx، هیچ «Refused to … Content-Security-Policy» |

> بیشتر سناریوها را یک بار با **مدیر سیستم** و یک بار با **کارشناس عادی** اجرا کنید: کارشناس نباید بخش‌هایی را
> که دسترسی‌اش را ندارد ببیند، و سرور هم باید رد کند.

## ۱۳. معیار پذیرش انتشار

- همهٔ ردیف‌های **P1** ✅ باشند.
- خطاهای P2 ثبت و یا رفع شوند یا آگاهانه پذیرفته شوند.
- در کل تست: هیچ 5xx، هیچ خطای قرمز Console، هیچ تخلف CSP.
- پیش از انتشار production: یک backup کامل با `backup.ps1` و یک بار تمرین بازیابی (BAK-03) روی سرور تست.

## ۱۴. نکته‌های انتشار که بر تست اثر دارند

- اگر روی production تقویم کاری **پیش‌فرض** تعریف شده، از این نسخه به بعد روزهای کاری همان تقویم ملاک موعدهاست
  (مثلاً پنج‌شنبه اگر در تقویم روز کاری باشد، موعد می‌پذیرد). CAL-01 تا CAL-08 را با تقویم واقعی سازمان هم اجرا کنید.
- `server.cjs` در گیت نیست: روی سرور پیش از `npm start` باید `npm run build` اجرا شود (روی IIS فقط `dist` منتشر می‌شود).
- Webhookها خاموش‌اند (`TaskManagement:Webhooks:Enabled=false`) و در این پلن نیستند.
